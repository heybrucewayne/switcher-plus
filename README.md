# Switcher +

Native macOS window switcher. It runs as an accessory utility, accepts Option–Tab through an Accessibility-authorized event tap, lists real app windows, and focuses the selected window when Option is released.

Open `Switchr.xcodeproj` in Xcode, build, then grant Accessibility permission when prompted. Screen Recording is requested only when window previews are needed; without it, each card falls back to the app icon and window title.

Option–Tab includes document windows across all Spaces and minimized windows discovered through Accessibility. Listing does not require a currently available capture surface. Hold Option and click a card to restore and focus that exact window, or release Option to commit the keyboard selection. Shift–Option–Tab goes backwards; Escape cancels. Cards wrap into rows based on screen width. The panel grows vertically up to the available screen height, then scrolls vertically without a visible scrollbar. Arrow keys navigate columns and rows; Option–Tab continues in reading order. Cards adapt to the available width, with large previews, overlapping app icons, and a blue selection outline.

Use “Enable window previews” in the switcher to grant Screen Recording access, then reopen the switcher (restart the app if macOS requests it). Previews preserve the window's aspect ratio. While running with permission, the app refreshes visible-window thumbnails every eight seconds and keeps up to 100 images in memory only. Minimized windows use their last captured image when available. A window minimized before any successful capture, or content macOS cannot capture, may show its app icon instead. No images are written to disk or transmitted.

Validation: Release macOS build passed with code signing disabled. The production SwiftUI views were rendered with six and eighteen synthetic windows, including a portrait preview, to check aspect ratio, clipping, and hidden scrollbars. This is layout validation, not proof of live capture accuracy. Real Accessibility/Screen Recording grants, mouse selection while holding Option, restoration across apps/Spaces, and minimized-window captures still require an interactive macOS check.

Window discovery filters Accessibility floating/unknown helper windows and deduplicates repeated AX elements and explicit native window IDs. Separate document windows remain separate, even with identical titles. Capture resolves windows by process and surface ID, with an unambiguous title/geometry fallback; minimized windows can reuse a matching cached surface. Uncaptured minimized windows still depend on macOS making a surface available.

Run the matching, restore-lookup, and grid regression checks with `swiftc Switchr/Models/WindowInfo.swift Tests/WindowMatchingChecks.swift -o /tmp/switcher-window-checks && /tmp/switcher-window-checks`. Finder/Brave capture and ChatGPT helper filtering still require verification against those apps with the installed build's permissions.

Version 1.5 merges the all-Spaces Window Server inventory with Accessibility windows. This fixes apps absent from AXWindows on inactive Spaces; untitled helper surfaces are excluded from the supplemental inventory. After selecting a window without an AX reference, focus retries AX resolution following app activation. Live discovery verification on the development Mac found 9 real windows, including 7 offscreen; actual Space-transition focus still needs interactive verification. The underlying AX limitation is also discussed in [AltTab issue 447](https://github.com/lwouis/alt-tab-macos/issues/447).

Version 1.6 restores minimized windows asynchronously, checks that minimization has cleared before raising, and retries focus during Dock/Space transitions. A unique title can resolve a minimized window whose frame changed; ambiguous titles are not guessed. Layout was rendered with 18 synthetic windows and checked at eight count/screen combinations. Physical minimize/restore interaction remains unverified.

Version 1.7 uses optional dynamically loaded AX SPI for exact window IDs and bounded off-Space handle lookup (1,000 tokens / 1.5 seconds, off the UI thread). Known valid AX handles are cached. The remote token ABI was checked against [OptionTab's AX declarations](https://github.com/andrealufino/optiontab/blob/main/optiontab/Services/AXPrivate.swift). If a listed surface cannot resolve to an actionable window, an application reopen event is sent; its resulting focused window is used instead of claiming the old surface was restored. Mail's specifically named iCloud Mail Cleanup utility is excluded, while mailboxes, messages, and drafts remain. Live read-only verification resolved current Mail windows but could not resolve several older CG surfaces; end-to-end restore/reopen still needs interactive verification.
